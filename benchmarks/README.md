# 实测对比与总结

记录两种答题方式的实际表现：**Codex 直接接管浏览器答题** 与 **油猴脚本辅助答题**。
所有数字都能复现（见文末命令），原始数据在 `runs/`。

## 一、两种方式的分工

| 对比项 | Codex 直接接管浏览器 | 油猴脚本（本项目） |
|---|---|---|
| 谁来操作 | 模型读页面 DOM、逐题判断、点选 | 同学自己点，脚本只标注 |
| 题库 | 同一份（3066 题） | 同一份 |
| 文字题 | 题库命中 + 语言推理 | 题库命中（精确 / 模糊 / 变体判定） |
| 变体题（同题干多套选项） | 逐题比对选项文本 | 同左（已固化为算法） |
| 图片题 | 模型也看不到图，靠选项语义判断 | 图片指纹命中；未收录的标"需人工判断" |
| 未命中时 | 给判断 + 说明依据 | 给"参考"（标注非题库答案）+ 需核对清单 |
| 依赖 | 需要模型在场 | 装完即用，离线、不联网 |

**关键澄清**：模型并不能"看到"图片（当前会话无图像输入能力）。它在图片题上的正确率来自
**选项语义 + 题目设计逻辑**（"具体指出隐患"的选项通常是答案，"只影响美观 / 属于正常现象"多为托词），
以及**读取成绩页的历史错题答案键**。这决定了"把能力迁移到脚本"的正确路径：
不是让脚本学会看图，而是把 ①答案键获取 ②语言规则 固化进脚本。

## 二、逐次实测记录

### A. Codex 直接接管（2026-10-14 ~ 10-15）

| 场次 | 题库状态 | 结果 | 错题 / 风险点 |
|---|---|---|---|
| 第 1 次 | 无题库（纯知识） | 99 分（该考试要求满分） | 3 题：清除污染口径、预防电气火灾"2人以上在场"、显示器电源 |
| 第 2 次 | 无题库 | 约 92.5 分 | 6 题：无毒试剂当危废、可燃气体泄漏先断电、细胞培养房气瓶、3D打印可随时停止、试电笔、铰孔倒转 |
| 第 3 次及以后 | 题库就绪（3437 题） | 通过 | 每卷仅 0~3 题需临场判断（图片题、变体题） |

结论：**没有题库时，错的全是"口径型"陷阱题**（与常识相反的题库标准答案）；
题库建立后，模型直接接管的缺口只剩"图片题 + 少量变体题"。

### B. 油猴脚本（同学自己作答）

原始数据：`runs/2026-10-15-run1-script-v0.3.json`、`runs/2026-10-15-run2-script-v0.4.4.json`

| 场次 | 脚本版本 | 诊断原始记录（确信/待核对/仅参考/无答案） | 当前引擎+题库重算 | 覆盖率 |
|---|---|---|---|---|
| 第 1 次 | v0.3.x | 54 / 12 / 11 / 3（82.5%） | **79 / 0 / 0 / 1（98.8%）** | 98.8% |
| 第 2 次 | v0.4.4 | 79 / 0 / 0 / 1（98.8%） | **79+2 / 0 / 0 / 0（100%）** | **100%** |

（"重算"= 用最新引擎 + 最新题库重新匹配；差值说明引擎修复与题库补录的价值。）

## 三、复盘：这轮踩过的三个坑

1. **徽章污染题干（v0.4.0 ~ v0.4.1）**
   徽章插在 `.question-title` 内部，重新扫描时题干变成"原题干 + 徽章文字"，相似度被拉低。
   实测把 **11 道本可命中的题误判成未命中**（第 1 份诊断：确信 54 → 79）。
   修复：徽章移到标题之外 + 取题干时剔除徽章（v0.4.2）。

2. **选项措辞差异（v0.2 及以前）**
   考试页与背题页同一选项会差几个字（"安全使用操作规程" vs "使用安全操作规程"），
   且题干一致但选项被改写时，评分公式会把同题压到阈值以下（实测 0.62）。
   修复：归一化流水线 + 联合评分 + 题干门（v0.3.0）。

3. **图片题**
   题库只覆盖背题模块的图片题，而考试会出该模块没有的图片题。
   修复：图片指纹匹配（同一张图直接命中）+ 未收录的标注"需人工判断"，
   并通过"考试诊断 → 归类 → 补录"的闭环持续补充（v0.4.0 起）。

## 四、量化对比

| 指标 | Codex 直接接管 | 油猴脚本（v0.4.5） |
|---|---|---|
| 文字题准确率 | 接近 100%（题库 + 推理） | 100%（题库，人工复核 0 题） |
| 图片题 | 靠选项语义判断 | 指题目录内直接命中；未收录需人工看一眼 |
| 每卷需人工介入 | 0~3 题 | 0~1 题（v0.4.4 实测） |
| 成本 | 需要模型在场 | 0（离线运行） |
| 可复制性 | 只能自己用 | 可发给同学直接用 |

工程侧指标（v0.4.5）：单元用例 26/26、全库自检 3068/3068、假 DOM 冒烟 10/10、
扰动鲁棒性评测 20864 例（误答 0，无答案 0）。

## 六、总结

- **题库是决定性的**：建立题库前模型也会连错（99 / 92.5 分）；建立后文字题基本归零。
- **模型与脚本不是替代关系**：模型的优势是语言推理与临场判断，脚本的优势是离线、可复制、零成本；
  实际最优是"脚本兜住 95% 以上，剩下 1~3 题（多为图片题）由人扫一眼或由模型判断"。
- **闭环比算法重要**：考试诊断 → 归类 → 补录题库 → 下次命中；这条链路跑通后，
  需人工核对的题会随每场考试单调下降（本轮实测：82.5% → 98.8% → 100%）。
